# Review Notes

The resize/scaling work introduces rendering regressions in several common window sizes: unscaled-but-letterboxed windows are drawn in the wrong place, downscaled modes crop the bottom/right edges, and odd-sized windows can leave stale padding visible. Those issues make the patch unsafe as-is.

## Full Review Comments

- [P2] Respect viewport offsets when the scale factor stays at 1x — `/home/bao/src/nullpomino/src/main/java/mu/nu/nullpo/gui/sdl/NullpoMinoSDL.java:955-956`
  When the window is resized to `640xN` or `Nx480`, `renderWidth`/`renderHeight` still match the logical framebuffer, but `renderOffsetX/Y` can be non-zero. This branch blits to `(0,0)` anyway, so the image is pinned to the top-left instead of centered, and `MouseInputSDL` still applies the offsets, which makes mouse interaction miss the visible UI in those window sizes.

- [P2] Include the last source row and column in downscaled blits — `/home/bao/src/nullpomino/src/main/java/mu/nu/nullpo/gui/sdl/NullpoMinoSDL.java:792-798`
  If the window is smaller than `640x480` (or fullscreen falls back to a lower resolution), these lookup tables never reach source indices `639`/`479`: `scaleMapX[renderWidth-1]` and `scaleMapY[renderHeight-1]` are always one short. The right and bottom edges of the 640x480 framebuffer are therefore never rendered in any downscaled mode, so borders and text at the edges get clipped.

- [P3] Clear odd-sized letterbox padding before scaled presentation — `/home/bao/src/nullpomino/src/main/java/mu/nu/nullpo/gui/sdl/NullpoMinoSDL.java:958-959`
  For odd-sized windows like `800x601`, `renderHeight` becomes `600` but `renderOffsetY` is `0`, so this guard skips clearing even though `scaleBlitToSurface` only writes 600 of the 601 rows. The remaining row/column keeps stale back-buffer pixels, which shows up as a thin garbage strip on the padded edge.
